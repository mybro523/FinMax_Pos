# Магазин без интернета: этапы 1–3 (ветка `bez-interneta`)

Ветка держит всё, что ещё не выпущено. В `main` этого нет: 01.11.2026 этап 1 (1.6.0) откачен
выпуском 1.6.1 по просьбе владельца — все три этапа выйдут вместе, по его команде.

## Как выпускать (когда скажут «выпускай»)

1. Новые коммиты `main` — слить в эту ветку, проверить (`npm test` в desktop, client, server).
2. Поднять версию программы (desktop/package.json, desktop/legacy/package.json и их lock-файлы)
   выше той, что сейчас в `main` (после 1.6.1 — например 1.7.0).
3. Слить ветку в `main` и отправить: сервер (Railway) и сайт (Vercel) выложатся сами.
4. Собрать обе программы (обычную и для Windows 7/8) и выложить в mybro523/finmax-updates.
   Сборка для магазинов берёт открытый ключ кодов только из `scripts/licence-pin.mjs` и сверяет его
   с сервером (`GET /api/licence/key`) — сервер к этому моменту уже должен быть с этой веткой.
5. Таблицу `LicenceKey` в базе сервиса не трогать никогда: в ней секретный ключ кодов активации
   (открытый ключ `d01cb7078be83f318094613d55663fa51b7a3d59b648b05821de0f97bf7a5464` закреплён в
   `server/src/common/licence-pin.ts` и `desktop/scripts/licence-pin.mjs`). При переезде базы —
   переносить как есть.

## Этап 1 — один компьютер без интернета, коды активации (готов, как 1.6.0)

Выбор при первом запуске «С интернетом / Без интернета», код активации ~50 знаков (подпись
сервиса, привязка к компьютеру, срок, число касс), магазин и владелец на этом компьютере, каждая
операция принимается сразу (`local/standalone.mjs`, `acceptAll`), сброс пароля владельца кодом,
копия на диск D каждый день и напоминание «на флешку», переезд на новый компьютер через
«Загрузить копию» (`soloAdopt`, `soloPrune`). Страница «Коды активации» — у владельца сервиса.

## Этап 2 — несколько касс по сети без интернета (начат)

Решения владельца (01.11.2026):
- касса подключается КОДОМ ПОДКЛЮЧЕНИЯ: на главном «Настройки» → «Кассы» → «Подключить кассу» —
  8 знаков на 10 минут; на новой кассе «Без интернета» → «Касса магазина» → код; главный
  находится в сети сам (или адрес вручную);
- главный — тоже касса: код «касс: 2» = главный + 1 касса;
- первый вход на кассе — и без главного: отпечатки паролей всех сотрудников копируются на кассу
  при подключении и при каждой смене;
- без главного касса работает без ограничения (до конца срока кода);
- конфликты (продано больше, чем было) — «Расхождения» на главном.

Устройство:
- Роли: в общей базе программы `soloRole` = 'register' у кассы (у главного — нет), `soloMain` —
  {deviceId, name, computer (5 байт hex), epoch, shopId}. Срок на кассе — код главного, проверка с
  кодом компьютера ГЛАВНОГО; новый код на главном уходит кассам в основе (`lic`).
- ЗВЕЗДА: касса говорит только с главным, главный — только со своими кассами (`hub.allow`;
  список касс — meta `soloPaired` в базе магазина главного, работают первые «касс − 1» по коду).
  Главный пересылает операции одной кассы остальным (его журнал обмена).
- Главный = «сервер»: свои операции принимает сразу (перед этим — в журнал, `lanCatchUp`), операции
  касс — как пришли (`mainAcceptPeers`); после каждого приёма пишет в журнал ОСНОВУ (запись 'base':
  принятые операции по порядку, основа затронутых товаров с партиями, покупателей, поставщиков,
  документы «сервера», тела смен, учётные записи сотрудников с паролем ключом магазина).
  Приём и запись основы — одной транзакцией.
- Касса: свои операции — поправкой, пока основа не назовёт их (`ackOp`); чужие — поправкой
  (`lanReceive`), основа подтверждает (`confirmOp`) и заменяет основу затронутых строк
  (`regApplyBase` → `rebuildStock`, `recountDebts`). Касса НЕ делает acceptAll/foldBase.
- Подключение: главный заводит ключ сети (meta `lanKey`, шифрование Windows), «поколение»
  `soloEpoch`, `shopId`. Код → K = scrypt(код); касса ищет главного по UDP ('finmax-pair', отпечаток
  K) или по адресу; `POST /lan/v1/pair` (тело и ответ шифрованы K) → сведения о магазине + база
  целиком (`shopSnapshot`: без очереди, журнала, соседей, ключа; WAL-заголовок → 1). Касса пишет
  файл, `regInstallDb` (соседом — главный с `gotUpTo` = место снимка), общая база: способ работы,
  роль, код активации главного, сотрудники с паролями. Один код — одна касса.
- Главный загрузил копию базы → новое «поколение» (`epochOk` не пройдёт), кассы подключаются
  заново (неотправленное кассы уходит главному в запросе подключения — `regPendingEntries`).
- Пароль, сменённый на кассе, уходит главному зашифрованным ключом магазина (`pwLan` в журнале,
  `lanCatchUp` с `pwOut`); главный кладёт его во вход и рассылает всем в основе.
- На кассе не делается (говорит «делается на главном компьютере»): ввод кода активации, сброс
  пароля кодом, «Загрузить копию», удаление покупателя (главный удаляет и рассылает в основе
  `gone`). Объединение карточек — недоступно, пока к магазину подключены кассы.
- Часы касс с сервером не сверены: проверка времени сообщений в магазине без интернета выключена
  (`anyTime`). Отметок о судьбе нет (`fates: false`). Журнал главного не чистится, пока его не
  получили все кассы (`lanPrune` с `keepAbove`), чужие операции не истекают (`expire: false`).

Готово и проверено линтером (не подключено к программе): `desktop/src/local/solonet.mjs`,
правки `desktop/src/lan.mjs` (код подключения, поиск, `/lan/v1/pair`, `allow`, `epochOk`,
`anyTime`), `desktop/src/local/lan.mjs` (`fates`, `pwOut`, запись 'base'), `standalone.mjs`
(`serverExtras` отдаёт документы).

Осталось:
1. gateway.mjs: роли и ключ сети главного; `lanEnabled` (касса — есть главный; главный — есть
   кассы или открыт код); `lanHub`: state (wide всегда, epoch, anyTime), allow, epochOk, pairInfo,
   pairFailed (20 неверных — код закрыт), pairServe; receive: главный — `lanReceive` + приём +
   основа, касса — операции пачками до основы, основа по порядку; `soloAccept` на главном —
   `catchUp` → (acceptAll + mainAccept) одной транзакцией → kick, на кассе — только журнал;
   пароли касс → вход главного (`soloPeerPassword`), учётные записи → кассам (`soloLogins`,
   `regLogins`); срок кассы с кодом главного; ограничения; `soloApi`: pairStart/pairStop/unpair/
   join; status: `solo` (роль, касса: главный на связи, ждут отправки; главный: кассы, код);
   tick: lanPrune с keepAbove, рассылка нового кода, конец кода подключения.
2. main.mjs/preload: IPC standalone:pairStart/pairStop/unpair/join; «Загрузить копию» на кассе — нет.
3. Окна: на первом запуске «Главный компьютер / Касса магазина», ввод кода подключения (и адреса);
   «Настройки» → «Кассы»: список касс, «Подключить кассу» (код с отсчётом), «Отключить»;
   значок состояния на кассе (главный на связи, ждут отправки); переводы на таджикский.
4. Проверки: gateway — главный + 2 кассы через настоящую сеть 127.0.0.1 (createLan на портах 0,
   pairRequest по адресу); e2e — три программы (FINMAX_LAN_TCP/UDP/BIND, APTEKA_DISK_ROOTS).

## Этап 3 — без интернета у клиентов С сервером (не начат)

Решения владельца (01.11.2026): клиентам с сервером тоже работают без связи — смена своего пароля,
объединение товаров, удаление покупателя, чеки и отчёты за год на кассе. Первый вход на новом
компьютере, «Расхождения», «Кассы» и срок работы без связи — по-прежнему через сервер.

## 05.11.2026 — НОВЫЕ РЕШЕНИЯ ВЛАДЕЛЬЦА (заменяют выбор «С интернетом / Без интернета»)

«Сделай так, чтобы приложение полностью работало без интернета, даже первый вход; вся база на
компьютере, на сервер ничего не отправлять». Кнопки:
- **Все магазины без интернета.** Выбора способа работы нет: программа всегда без сервера. Облачный
  код остаётся спящим. Нынешние магазины — тестовые: после обновления вход их сотрудников с
  компьютера убирается, магазин заводится заново (старые файлы баз не трогаем).
- **Без кода активации** (позже, может быть, вернём): срока нет, касс сколько угодно. Механизм кодов
  не удаляется — выключен одним флагом (`requireCode`).
- **Сразу несколько касс по сети** — доделать этап 2 (ниже, «Осталось»).
- Ключ кодов — прежний (d01cb707…): им подписываются **коды сброса пароля владельца** (их выдаёт
  владелец сервиса в панели, как в 1.6.0).
- Обновления — с GitHub сами, если интернет есть (на сервер ничего не уходит); иначе установщик с флешки.
- **Логотип** — в программе: «Настройки» → «Чек и печать» на главном; кассы получают его по сети.
- К серверу FinMax программа не обращается вовсе (ни обмена, ни постоянного соединения, ни проверки
  адресов 1.6.5).
